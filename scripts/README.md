# SKU 카탈로그 메타데이터 처리

## 1. 실행 방법

### 환경변수 설정

`.env`에 Gemini API Key를 설정한다.

```text
GEMINI_API_KEY=...
```

### 정답 SKU 이미지 준비

실제 상품 이미지 5장을 SKU별 폴더에 저장한다.

```text
data/
└── catalog/
    └── answer_sku/
        └── CHR-DIN-001/
            ├── main.jpg
            ├── angle_1.png
            ├── angle_2.png
            ├── angle_3.png
            └── angle_4.png
```

### 실행

```bash
python scripts/extract_answer_sku_metadata.py
```

처리 흐름:

```text
상품 이미지 5장
    ↓
Gemini VLM
    ↓
메타데이터 추출
    ↓
catalog_spec.py 기준 검증
    ↓
answer_sku.json 저장
```

결과:

```text
data/catalog/answer_sku.json
```

---

## 2. `catalog_spec.py`

가구 카탈로그의 **분류 체계, 메타데이터 속성, 허용값을 정의하는 단일 기준**이다.

### 카탈로그 구성

```text
4개 대분류 × 3개 소분류 = 12개 소분류
12개 소분류 × 12 SKU = 144 SKU
144 SKU × 5장 = 720장
```

> 위 수치는 현재 실제 데이터가 아니라 향후 카탈로그 구성 계획이다.

### 분류 체계

```text
의자
├── 식탁의자
├── 사무용의자
└── 스툴·바의자

테이블
├── 식탁
├── 책상
└── 거실·사이드테이블

소파·안락가구
├── 일반 소파
├── 암체어·안락의자
└── 소파베드·카우치

수납가구
├── 책장·선반유닛
├── 수납장·장식장
└── 서랍장·침대협탁
```

### 메타데이터

모든 가구에 공통으로 적용되는 속성과 대분류별 전용 속성으로 구성한다.

```text
상품 속성
=
공통 속성
+
대분류 전용 속성
```

공통 속성:

```text
색상 / 스타일 / 무늬
```

대분류별 전용 속성:

| 대분류     | 전용 속성                                 |
| ------- | ------------------------------------- |
| 의자      | 유형, 주요 소재, 등받이 형태, 다리 형태, 팔걸이         |
| 테이블     | 유형, 형태, 상판 소재, 프레임 소재, 다리 형태, 우드톤     |
| 소파·안락가구 | 유형, 인원, 형태, 주요 소재, 팔걸이, 헤드레스트         |
| 수납가구    | 유형, 설치 형태, 단 수, 주요 소재, 도어 형태, 서랍, 우드톤 |

`유형`은 소분류와 중복되지 않도록 **구조·형태·사용 방식 중심**으로 정의한다.

예:

```text
소분류 = 식탁의자
유형   = 일반형
```

## 3. `extract_answer_sku_metadata.py`

실제 상품 이미지에서 Gemini VLM을 이용해 메타데이터를 추출하고 검증하는 스크립트이다.

현재는 테스트를 위해 SKU 기본 정보와 이미지 경로를 하드코딩한다.

```text
SKU_CODE     = CHR-DIN-001
PRODUCT_NAME = TEODORES 테오도레스
BRAND        = IKEA
CATEGORY     = 의자
SUB_CATEGORY = 식탁의자
```

처리 과정:

1. SKU 이미지 5장 로드
2. `catalog_spec.py`에서 속성과 허용값 조회
3. 허용값을 포함한 VLM 프롬프트 생성
4. Gemini VLM으로 메타데이터 추출
5. 필수 속성 및 허용값 검증
6. `answer_sku.json`에 저장

검증을 통과하지 못하면 저장하지 않는다.

동일한 `sku_code`가 존재하면 기존 데이터를 교체하여 **Upsert 방식으로 갱신**한다.

---

## 4. 결과 예시

```json
{
  "sku_code": "CHR-DIN-001",
  "product_name": "TEODORES 테오도레스",
  "brand": "IKEA",
  "category": "의자",
  "sub_category": "식탁의자",
  "attributes": {
    "색상": "화이트",
    "스타일": "미니멀",
    "무늬": "무지",
    "유형": "일반형",
    "주요 소재": "플라스틱",
    "등받이 형태": "미드백",
    "다리 형태": "4다리",
    "팔걸이": "없음"
  }
}
```

## 5. 파일 관계

```text
catalog_spec.py
   │
   │ 속성·허용값 제공
   ↓
extract_answer_sku_metadata.py
   │
   ↓
Gemini VLM
   │
   ↓
메타데이터 추출
   │
   ↓
catalog_spec 기준 검증
   │
   ↓
answer_sku.json
```

현재는 **메타데이터 추출 및 검증까지 구현**되어 있으며, 이미지 임베딩과 SKU 검색·매칭은 이후 구현한다.

실제 크롤링 데이터가 준비되면 현재 하드코딩된 SKU 정보와 이미지 수집 부분을 크롤링 데이터로 교체하여 자동화할 예정이다.

# 6. 테스트

`pytest`를 사용하여 메타데이터 추출 파이프라인의 주요 기능을 검증한다.

## 테스트 범위

| 테스트 항목 | 검증 내용 |
|---|---|
| 1. 이미지 정상 로딩 | 대표 이미지 1장 + 각도 이미지 4장, 총 5장이 정상적으로 로드되는지 확인 |
| 2. 이미지 누락 예외 | 이미지가 하나라도 없을 경우 `FileNotFoundError`가 발생하는지 확인 |
| 3. 프롬프트 카테고리 정보 | 프롬프트에 대분류와 소분류가 포함되는지 확인 |
| 4. 프롬프트 허용값 | `catalog_spec.py`의 속성과 허용값이 프롬프트에 포함되는지 확인 |
| 5. 정상 메타데이터 검증 | 모든 필수 속성이 존재하고 허용값을 사용하는 경우 통과하는지 확인 |
| 6. 필수 속성 누락 검증 | 필수 속성이 누락된 경우 `ValueError`가 발생하는지 확인 |
| 7. 잘못된 속성값 검증 | 허용되지 않은 값이 포함된 경우 `ValueError`가 발생하는지 확인 |
| 8. 전체 파이프라인 | Mock Gemini를 사용하여 이미지 로드 → 프롬프트 생성 → 메타데이터 추출 → 검증 → JSON 저장까지 정상 동작하는지 확인 |

실제 Gemini API를 호출하지 않고 `FakeGeminiService`를 사용하여 테스트하므로 API Key 없이도 테스트할 수 있다.

```text
이미지 로드
    ↓
프롬프트 생성
    ↓
Mock Gemini
    ↓
메타데이터 검증
    ↓
answer_sku.json 저장
    ↓
전체 결과 검증
```

현재 테스트는 **메타데이터 추출 파이프라인의 기능 및 예외 처리를 검증하는 목적**이며, 실제 Gemini 모델의 판단 정확도 자체를 평가하는 테스트는 포함하지 않는다.
